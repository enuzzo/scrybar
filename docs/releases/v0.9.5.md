# v0.9.5 / r322 quality and release record

Date: 2026-10-23. This release joins the completed display-performance work,
network Stats redesign, native theme/text review, responsive web interfaces and
Companion artwork recovery. Implementation, hardware observations, user
acceptance and publication are recorded separately below.

## Implementation and verification

| Area | Result and evidence |
| --- | --- |
| Display pacing | r322 hardware: 60.0 completed-DMA fps during active cached HOME/INFO motion under delayed-header and slow-receiver HTTP traffic; zero missed scheduling periods. With final Companion53 active, 1,170 intervals had a maximum of 20.443 ms (earlier r322 trial: 20.779 ms). This is not optical scanout measurement or a guarantee that every interval is 16.667 ms. [Workload, raw accounting and limits](../performance/2026-10-23-frame-pacing.md) |
| Network Stats | Larger history area, timestamp-based sampling, continuous known segments and explicit gaps for missing data. The owner accepted the corrected curves on the physical display. |
| Physical interaction | The owner accepted continuous swipes, canceled drags and held drags on r320. Later r321/r322 performance regressions passed; this does not relabel that acceptance as a new physical r322 review. |
| Native design | Seven themes, 70 normal page renders, long-label/state fixtures, 14 languages and word-clock boundaries reviewed using actual LVGL layout and fonts. Final r322 native drawing is equivalent to the reviewed r321 drawing after firmware-tag normalization. [Native review](../design/2026-10-23-display-quality/native-pages.md), [r322 equivalence](../design/2026-10-23-display-quality/r322-equivalence.md) |
| Embedded Control | Display, Wi-Fi and Content sections; accessible controls, mobile action bar, saved/live-preview brightness distinction. Actual device save/reload/reset tests restored the initial configuration. |
| Product/installer site | Interactive view/theme preview, responsive navigation, version-aligned installer, retry/failure states and concise download information. Chromium and WebKit tests cover narrow phone widths; an actual iPhone/Safari session was not performed. [Web evidence and scope](../design/2026-10-23-webui/QA.md) |
| Album artwork | The old producer could supply valid TIDAL metadata while returning no cover. The Companion now reads native MediaRemote artwork, checks complete track/source identity and keeps image work off metadata polling. Per-display refresh restores RAM-only images after a restart. [Companion diagnosis, package and runtime checks](companion-0.3.15.md) |
| Image resolution | ScryBar receives native 150 px RGB565. Meguru receives native artwork promptly and upgrades only when a genuine source of at least 512 px passes metadata and pixel matching. No enlarged thumbnail is represented as HD. |
| Public firmware provenance | Isolated clean build used the approved r322 sources, empty public Wi-Fi defaults and no private configuration. Public DOOM is disabled. [Preflight and build receipt](v0.9.5-preflight.md) |

The installed ScryBar app-only build retains its existing configuration,
partition table and filesystem. Public installer files are a separate clean
build and are never copied from an owner-device flash backup.

## Publication receipt

The authorized publication uses a selected snapshot based on public main,
excluding local credentials, backups, raw music/device captures, generated
dependencies, old application packages, the personal Diagnostics image and the
DOOM WAD. It does not push the development checkout's 29 unpublished historical
commits. Companion remains an explicitly ad-hoc-signed, non-notarized preview
for macOS 14+, universal Apple Silicon and Intel.

Publication identifiers, final checksums, workflow outcome and public download
verification will be added here after those external checks complete. Local
builds alone do not establish public availability.

## Checkout and generated-file handoff

The original development main and its uncommitted work are preserved. The
curated public commit has a separate ancestry from that local development
history; inspect both histories before the next pull, merge or push. Do not
force-push or reset the development checkout to reconcile them.

All new build/dependency outputs were prepared outside Dropbox. The existing
ignored and untracked `web/.astro` cache lacked the local File Provider exclusion;
the exclusion was applied and verified before reuse. Its previous contents may
already have synchronized. Other Macs must prepare their own exclusion before
regenerating this cache; the attribute is local to this Mac.
