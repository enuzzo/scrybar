# ScryBar website

The public product page is built with Astro 7 as static HTML. Small vanilla JavaScript modules handle the nine-view preview, seven theme choices, mobile menu, image dialog and ESP Web Tools installer. There is no React/Vue runtime.

The device configuration page is a separate interface, generated by the web builders in `scrybar.ino`; it is not served by Astro.

| Content | Owning source |
| --- | --- |
| View names, captions, fourteen clock languages and seven themes | `src/data/product.ts` |
| Page composition and questions | `src/pages/index.astro` |
| Gallery, theme choices and enlarged preview | `src/components/ProductPreview.astro` |
| Browser installer states and manifest URLs | `src/components/FlashSection.astro` |
| Current Companion download and installation notes | `src/components/CompanionApp.astro` |
| Color/type tokens and responsive layout | `src/styles/tokens.css`, `global.css`, `sections.css` |
| Public firmware manifest | `public/manifest.json` |
| Browser regression checks | `tools/browser-qa.mjs`, `tools/control-panel-qa.mjs`, `tools/brightness-state-qa.mjs` |

Home captures and Mac Stats examples follow all seven theme choices: Default, Cyberpunk 2077, Toxic Candy, Tokyo Transit, Mono, Mint Protocol and Cathode Ray. Other views retain the theme of their capture; the interface states this next to the selector. Mac Stats and Diagnostics use native firmware renders with explicitly labelled sample data. Old, unreferenced source captures are not part of the generated page.

## Local work outside Dropbox

Node 22.12 or later and the checked-in `package-lock.json` are required. Use `npm ci`; do not update the lockfile merely to set up another Mac. Fonts load from Google Fonts with system fallbacks.

When the repository is in Dropbox, prepare dependencies, Astro caches and build output in an external working copy. From this `web/` directory:

```sh
repo_web="$PWD"
web_work="$(mktemp -d "${TMPDIR:-/tmp}/scrybar-web.XXXXXX")"
rsync -a --exclude node_modules --exclude .astro --exclude dist --exclude .cache "$repo_web/" "$web_work/"
cd "$web_work"
npm ci --no-audit --no-fund --cache "$web_work/npm-cache"
npm run dev -- --host 127.0.0.1
```

Make source edits in the repository and copy them to the external working directory with the same exclusions. Keep `node_modules`, `.astro` and caches there. If dependencies are ever prepared inside Dropbox instead, apply and verify the user's Git/File Provider exclusion rules **before** creating populated dependency directories.

For an inspectable production preview, run these commands in that external copy:

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 5181
```

The ROOT build uses `/`. GitHub Pages uses `PAGES_BASE=/scrybar`; validate that build separately:

```sh
PAGES_BASE=/scrybar npm run build -- --outDir /tmp/scrybar-pages-dist
```

The release workflow resolves the firmware version and updates the public manifests before Astro renders the page. Firmware binaries are assembled by CI; local website builds do not fabricate or publish firmware files. A successful website build does not establish USB installation or device compatibility.

## Browser checks

Provide an **existing** Playwright installation and its browser engines; the scripts do not install dependencies or request a serial port. Write reports/screenshots outside the synced repository during iteration.

```sh
SCRYBAR_PLAYWRIGHT_MODULE=/absolute/path/to/playwright node tools/browser-qa.mjs --url http://127.0.0.1:5181/ --out /tmp/scrybar-site-qa
SCRYBAR_PLAYWRIGHT_MODULE=/absolute/path/to/playwright node tools/browser-qa.mjs --engine webkit --widths 320,390 --url http://127.0.0.1:5181/ --out /tmp/scrybar-site-webkit-qa
```

The website checks cover responsive geometry, menu/keyboard behavior, all view/theme combinations, dialog focus, reduced motion and installer fallbacks. Installer success/error paths use an explicitly mocked loader. Control Surface checks require a local fixture server, never a device URL; they exercise form choices and transport contracts without claiming NVS persistence. Responsive Chromium/WebKit results are not physical iPhone acceptance.
